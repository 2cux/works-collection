## 1. 设计目标

本网站是个人作品展示网站，不是后台管理系统，也不是普通简历页面。

设计目标：

- 第一眼有吸引力
- 页面精美、有质感
- 项目展示清晰
- 技术氛围强
- 桌面端和移动端都好看
- 适合 GitHub、简历和面试展示

## 2. 整体风格

推荐风格：

- 深色科技风
- 现代作品集风格
- AI 产品展示风格
- 渐变光效
- 玻璃拟态卡片
- 大字号标题
- 精致按钮
- 柔和阴影
- 轻量动效

视觉关键词：

- Dark Mode
- Gradient
- Glassmorphism
- Glow
- Modern Portfolio
- Premium Cards
- AI Product Showcase
- Clean Engineering
- Responsive Design

## 3. 页面气质

页面应该像：

- 一个精美的开发者作品集
- 一个 AI 产品展示页
- 一个能吸引面试官继续看的项目展示网站

页面不应该像：

- 后台管理系统
- 简历 Word 文档
- 普通模板页面
- 信息堆砌页面
- 颜色杂乱的练手网页

## 4. 色彩建议

### 4.1 背景色

推荐使用深色背景，例如：

- #020617
- #030712
- #0f172a
- #111827

可以叠加渐变光斑：

- 蓝色光斑
- 紫色光斑
- 青色光斑

### 4.2 主色

推荐：

- Blue
- Cyan
- Violet
- Indigo

示例：

- #38bdf8
- #818cf8
- #a855f7
- #22d3ee

### 4.3 文字色

推荐：

- 主标题：接近白色
- 正文：灰白色
- 辅助文字：灰色
- 标签文字：浅色

示例：

- text-white
- text-slate-200
- text-slate-300
- text-slate-400

## 5. 字体层级

### 5.1 Hero 标题

桌面端：

- 字号应足够大
- 推荐 text-5xl 到 text-7xl
- 字重推荐 font-bold 或 font-semibold
- 行高紧凑但不拥挤

移动端：

- 推荐 text-4xl
- 避免过长一行溢出

### 5.2 Section 标题

推荐：

- text-3xl 到 text-5xl
- 字重清晰
- 可加入小号 eyebrow 文案，例如 Featured Works

### 5.3 正文

推荐：

- text-base 到 text-lg
- 行高舒适
- 不要一屏堆太多长段落

## 6. Hero 设计要求

Hero 是最重要区域。

必须做到：

- 第一屏有视觉冲击力
- 主标题足够突出
- 副标题清晰表达个人方向
- 按钮明显且精致
- 背景有渐变光效
- 不要信息过载

Hero 推荐内容：

主标题：

Building AI Products with Clean Engineering

副标题：

我专注于 AI 应用开发、RAG 知识库问答系统、Java 后端工程和前后端分离项目交付。

按钮：

- View My Works
- GitHub

Hero 可以包含一个模拟项目预览卡片，用于展示 AI 知识库问答平台的产品感。

## 7. 卡片设计要求

作品卡片必须有高级感。

推荐样式：

- 圆角：rounded-2xl 或 rounded-3xl
- 背景：半透明深色
- 边框：细边框，例如 border-white/10
- 阴影：柔和阴影
- 悬浮：轻微上浮
- 光效：hover 时边框或背景轻微变亮

卡片不应该：

- 像后台表格
- 内容太拥挤
- 图片大小不统一
- 文字过多
- 颜色过杂

## 8. 图片展示要求

项目截图是作品集网站的核心视觉内容。

所有截图必须：

- 使用统一比例
- 推荐 16:9
- 不允许拉伸变形
- 使用 object-cover 或 object-contain
- 卡片高度统一
- 图片之间间距统一
- 移动端单列展示

当前项目截图顺序：

1. 登录页面
2. 知识库列表
3. 文档管理
4. 问答对话

没有真实截图时，必须展示美观占位卡片，不要出现 broken image。

## 9. 布局建议

### 9.1 桌面端

推荐：

- 内容最大宽度 max-w-7xl
- 页面左右留白充足
- Hero 可以左右分栏
- 作品卡片可以使用大卡片布局
- 截图墙使用两列网格

### 9.2 移动端

必须保证：

- 不横向滚动
- 单列布局
- 标题不溢出
- 按钮容易点击
- 图片比例稳定
- 卡片上下间距舒适
- 导航不要拥挤

## 10. 动效规范

可以使用轻量动效：

- 首屏淡入
- 卡片 hover 上浮
- 按钮 hover 光效
- 截图卡片进入视口时淡入
- 背景渐变轻微变化

不要使用：

- 大量旋转
- 强烈闪烁
- 复杂 3D 动画
- 影响阅读的动画
- 导致页面卡顿的动效

## 11. 技术栈展示设计

技术栈不要做成普通表格。

推荐展示方式：

- 分组卡片
- 标签 pill
- 简洁图标
- 网格布局

分组：

Frontend:

- React
- TypeScript
- Vite
- Tailwind CSS

Backend:

- Java
- Spring Boot
- MyBatis-Plus
- RESTful API

Database & Middleware:

- MySQL
- Redis
- RabbitMQ

AI Application:

- RAG
- Embedding
- LLM API
- Prompt Engineering

DevOps:

- Docker
- GitHub
- Linux Server
- Environment Variables

## 12. 多作品扩展设计

虽然第一版只有一个作品，但视觉结构必须支持多个作品。

Works Grid 应该支持：

- 一个作品时不显得空
- 两到三个作品时布局平衡
- 更多作品时可自然扩展
- 每个作品有统一卡片样式

不要把页面写死成只展示一个项目。

## 13. 文案风格

文案应当：

- 简洁
- 专业
- 面向展示
- 突出项目价值
- 突出技术能力
- 避免大段堆砌

推荐表达：

- 我构建了一个基于 RAG 的 AI 知识库问答平台
- 该项目将文档上传、解析、向量化和问答生成整合为完整链路
- 项目关注知识检索、答案可追溯、工程化部署和前后端分离交付

避免表达：

- 我做了一个简单项目
- 这是一个练手项目
- 功能很多很多
- 页面随便写的

## 14. 验收标准

设计完成后，需要满足：

- 首屏足够吸引人
- 页面不像后台系统
- 项目展示清楚
- 图片比例统一
- 移动端不变形
- 多作品结构可扩展
- 动效克制
- 视觉风格统一
