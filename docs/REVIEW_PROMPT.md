# Review Prompt

你现在是前端代码审查 AI，请对当前 Works Collection 作品集网站进行代码审查。

## 1. 项目定位

这是一个个人作品展示网站，只用于展示项目作品、项目截图、技术能力和联系方式。

它不是复杂业务系统。

第一版重点展示：

AI Knowledge Base QA Platform / AI 知识库问答平台

但代码结构必须支持未来添加多个作品。

## 2. 技术栈

当前项目计划使用：

- React
- Vite
- TypeScript
- Tailwind CSS
- Framer Motion
- lucide-react

请不要建议引入不必要的大型依赖。

## 3. 非目标检查

请重点检查是否误加了以下不该做的功能：

- 登录注册
- 后台管理
- 数据库
- 后端 API
- 在线上传作品
- 博客 CMS
- 评论系统
- 搜索系统
- 用户系统
- 权限系统
- 复杂路由
- 动态项目管理后台

如果发现以上功能，请指出并建议删除或暂缓。

## 4. 功能完整性审查

请检查页面是否包含以下模块：

- Navbar
- Hero
- Featured Works
- Works Grid
- Selected Work Showcase
- Visual Gallery
- Tech Stack
- Contact
- Footer

请检查当前主作品是否展示完整：

- 项目名称
- 中文名称
- 项目简介
- 技术标签
- 项目亮点
- 截图展示
- GitHub 链接
- Demo 链接占位

## 5. 多作品扩展性审查

请重点检查：

- 页面是否写死只支持一个作品
- 是否使用 src/data/works.ts 管理作品数据
- 是否定义清晰的 Work 类型
- Works Grid 是否通过数据渲染
- Featured Works 是否通过 featured 字段筛选
- Gallery 是否通过作品 screenshots 渲染
- 新增第二个作品时是否需要大改组件

验收要求：

新增作品时，只应该需要：

1. 添加 public/works/{work-slug}/ 图片资源
2. 在 src/data/works.ts 新增作品对象
3. 页面自动展示新作品

不应该重写核心组件。

## 6. 视觉质量审查

请检查：

- 页面是否精美
- 是否有现代科技感
- 是否不像后台管理系统
- Hero 是否有视觉冲击力
- 项目卡片是否高级
- 截图墙是否整齐统一
- 技术栈区域是否清晰
- Contact 区域是否简洁
- 页面是否存在信息堆砌

请指出视觉上最影响观感的问题。

## 7. 响应式适配审查

请检查：

- 桌面端布局是否正常
- 平板端布局是否自然
- 移动端是否单列展示
- 是否存在横向滚动
- 字号是否过大或过小
- 按钮是否易点击
- 卡片间距是否舒适
- Hero 在手机端是否过于拥挤

如果有移动端问题，请给出具体修改建议。

## 8. 图片展示审查

请检查：

- 截图是否统一 16:9
- 图片是否变形
- 图片是否被裁切过度
- 缺失图片时是否有占位展示
- 是否出现 broken image
- 图片卡片尺寸是否一致
- 桌面端是否两列展示
- 移动端是否单列展示

当前主项目截图顺序应为：

1. 登录页面
2. 知识库列表
3. 文档管理
4. 问答对话

## 9. 代码质量审查

请检查：

- 组件拆分是否清晰
- TypeScript 类型是否合理
- 数据是否和 UI 分离
- 是否存在重复代码
- 是否存在无用依赖
- 是否存在过度复杂逻辑
- Tailwind class 是否过于混乱
- 是否存在不可维护的硬编码
- 组件命名是否清晰
- 文件结构是否合理

## 10. 性能与可维护性审查

请检查：

- 是否存在明显性能问题
- 动效是否过度
- Framer Motion 是否使用克制
- 图片加载是否合理
- 后续增加项目是否方便
- 是否有不必要的状态管理
- 是否有不必要的复杂抽象

## 11. 构建检查

请确认以下命令是否能成功：

    npm install
    npm run dev
    npm run build

如果不能成功，请指出错误原因和修复建议。

## 12. 输出格式

请按以下格式输出审查结果：

### 1. 总体结论

通过 / 不通过 / 基本通过但需要修改

### 2. 主要问题

列出当前最影响质量的问题。

### 3. 必须修改的问题

列出不改就不能进入下一阶段的问题。

### 4. 可选优化项

列出可以后续优化的问题。

### 5. 具体修改建议

尽量指出应该修改的文件、组件和原因。

### 6. 下一步建议

说明当前是否可以进入下一模块开发，或者应该先修复哪些问题。
